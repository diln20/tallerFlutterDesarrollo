Una regla: no volver a pegar una versión anterior

Esta es la implementación integrada. En las etapas iniciales el objeto Vehiculo tenía únicamente nombre y disponibilidad; luego se agregaron imágenes como bytes temporales. La versión final conserva el ID real, nombre, marca, precio, disponibilidad, URL de la foto y favoritos. Los pasos previos enseñan conceptos, pero no se deben copiar directamente sobre los archivos finales.
ANTES · LISTA LOCAL

Vehiculo(nombre, disponible) + List<Vehiculo> dentro de la página.

Adecuado para entender variables y setState, pero no conserva datos.

DESPUÉS · MODELO DEFINITIVO

Vehiculo(id, nombre, marca, precio, disponible, imagenUrl, esFavorito) y VehiculoRepository.

El backend crea los ID y almacena autos, fotos y favoritos.

02

Crear los modelos

lib/models/vehiculo.dart lib/models/usuario.dart

Los modelos no dibujan pantallas. Vehiculo.fromJson interpreta la respuesta recibida; DatosVehiculo.toJson prepara lo que se envía al servidor. Un usuario es otro objeto, no una propiedad del vehículo.

enum RolUsuario { administrador, vendedor, cliente }

// Ejemplo de lectura en el modelo actual:
final nombre = json['nombre'] as String;
final precio = (json['precio'] as num).toDouble();

El id del vehículo llega desde la API. Un formulario nuevo nunca debe inventar el ID. json proviene del método fromJson del archivo real.

03

Separar services de repositories

lib/services/api_service.dart lib/repositories/vehiculo_repository.dart

El servicio conoce direcciones, métodos HTTP, cabeceras y JSON. El repositorio ofrece operaciones comprensibles para el catálogo como crear, editar, eliminar, listar, subirImagen y cambiarFavorito. La página no necesita preparar peticiones HTTP.

final nuevo = await _repositorio.crear(formulario.datos);
if (formulario.imagen != null) {
  await _repositorio.subirImagen(nuevo.id, formulario.imagen!);
}

Este fragmento resume dos operaciones consecutivas. En la implementación real primero se comprueba si se seleccionó una fotografía, se conserva el ID al editar y se capturan los errores.

04

Cargar fotos en navegador y móvil

lib/services/imagen_service.dart

Usa image_picker + XFile.readAsBytes(). Eso permite seleccionar archivos sin importar dart:io, incompatible con Flutter web.

final XFile? archivo = await _picker.pickImage(
  source: ImageSource.gallery,
  maxWidth: 1600,
  imageQuality: 75,
);
if (archivo == null) return null;
final bytes = await archivo.readAsBytes();

await espera al usuario; XFile? permite cancelación; Image.memory muestra la vista previa; Image.network muestra la foto después de guardarla en el servidor. Se admiten JPEG, PNG y WebP, máximo 5 MB. El backend comprueba también el contenido real.

05

Construir el formulario reutilizable

lib/widgets/vehiculo_form_dialog.dart

Explica uno por uno: Form, GlobalKey<FormState>, TextEditingController, TextFormField, validator, SwitchListTile, selección de imagen y botones.

El formulario utiliza SingleChildScrollView, así el teclado del teléfono no obliga a que toda la pantalla desborde. Los controladores se liberan en dispose().

¿Dónde quedó guardarVehiculo?

En esta versión el método de página se llama _guardarVehiculo(Vehiculo? anterior) y está en lib/pages/catalogo_page.dart; abre el modal y llama al repositorio. Dentro de VehiculoFormDialog, el método _guardar() valida los campos y entrega los datos al callback onGuardar. No son dos implementaciones distintas del CRUD: forman parte del mismo flujo.

06

Crear el listado con ListView.builder

lib/pages/catalogo_page.dart

itemCount es la cantidad de registros recibidos y itemBuilder genera cada tarjeta. Al anidar el listado dentro del desplazamiento general, el ejemplo final usa shrinkWrap: true y NeverScrollableScrollPhysics.

ListView.builder(
  shrinkWrap: true,
  physics: const NeverScrollableScrollPhysics(),
  itemCount: datos.datos.length,
  itemBuilder: (context, index) {
    final vehiculo = datos.datos[index];
    return VehiculoCard(
      key: ValueKey(vehiculo.id),
      vehiculo: vehiculo,
      urlImagen: widget.api.urlImagen,
      onFavorito: () => _favorito(vehiculo),
      onEditar: puedeEditar
          ? () => _guardarVehiculo(vehiculo)
          : null,
      onEliminar: puedeEliminar
          ? () => _eliminar(vehiculo)
          : null,
    );
  },
)

El fragmento es explicativo: consulta catalogo_page.dart para los argumentos completos del widget.

07

Añadir filtros, favoritos y paginación

Conserva el catálogo original y añade búsqueda por modelo/marca, precio máximo, disponibilidad, orden ascendente/descendente, favoritos personales y botones de página. Los filtros se aplican en el servidor; al cambiar uno se regresa a la primera página.

La búsqueda aplica una espera de 330 ms antes de enviar solicitudes. Los campos y selectores utilizan LayoutBuilder para ocupar el ancho disponible en pantallas inferiores a 650 px. Cada menú desplegable también usa isExpanded: true para evitar el desbordamiento del texto.

08

Agregar las pantallas por perfil y los permisos

lib/pages/usuarios_page.dart

Administrador: gestiona cuentas y vehículos. Vendedor: registra y edita vehículos. Cliente: consulta y marca favoritos. El menú usa NavigationBar en teléfono y NavigationRail en escritorio; IndexedStack evita reiniciar cada página al cambiar de tab.

if (widget.usuario.esAdministrador)
  UsuariosPage(api: widget.api, actual: widget.usuario)

Ese if cambia la interfaz, pero la API comprueba los permisos de nuevo. Ante una operación no permitida devuelve 403.

Autenticación frente a autorización

La autenticación comprueba quién es la persona. La autorización valida cada operación. Aunque alguien haga aparecer un botón con herramientas de navegador, el backend debe seguir rechazando la acción.

HTTP Basic con contraseñas demo solo sirve para un laboratorio local. No lo despliegues como servicio público.

Prueba automática de toda la aplicación

Una prueba no se limita a que el programa compile. También necesitamos comprobar que el formulario, el servicio HTTP, el repositorio y la base de datos realmente intercambian información. Para eso incorporamos una prueba E2E (de extremo a extremo) ejecutada con Chrome.

09

Ejecutar el flujo completo con un navegador real

actividad2a/scripts/e2e-web.js

Con la API en el puerto 8091 y la compilación web servida en el 5174, entra en la carpeta scripts y ejecuta:

npm install
npm run test:e2e

El script abre Chrome, inicia sesión, registra un vehículo, selecciona una fotografía PNG real desde el navegador, comprueba la URL persistente, guarda favoritos y verifica las diferencias entre administrador, vendedor y cliente. Además, cambia la pantalla a 390 × 844 para comprobar la navegación móvil y revisa los errores JavaScript.

El vehículo de prueba se elimina al finalizar y la prueba solo se permite contra servidores locales. Consulta el código y los requisitos para ejecutarla.

Importante para clase: que la versión web haya pasado la prueba real no garantiza que la cámara funcione en todos los teléfonos. El proyecto Android compiló correctamente, pero los permisos y la selección de fotos deben probarse también en un dispositivo físico. iOS requiere macOS y Xcode.
