Preparar y ejecutar el proyecto

Antes de escribir Flutter, comprobemos que nuestro entorno funciona y sepamos en qué carpeta vamos a trabajar.

✦
Al terminar podrás

Ubicar el proyecto, revisar el entorno de Flutter y abrir la aplicación en un dispositivo o emulador.

1. Reconocer el proyecto

Flutter organiza una aplicación en varias carpetas. Por ahora nos interesan estas tres piezas:

lib/main.dart

Es el archivo donde se encuentra el código Dart principal de la aplicación.

pubspec.yaml

Define el nombre del proyecto, la versión y las dependencias necesarias.

android/ y web/

Contienen archivos de soporte para ejecutar Flutter en distintas plataformas.

2. Comprobar Flutter

Abre PowerShell o la terminal de tu editor y ejecuta el diagnóstico. No modifica tus archivos.

Terminal · verificar instalación
flutter doctor
flutter devices
flutter doctor

Comprueba la instalación de Flutter y muestra herramientas que podrían faltar.

flutter devices

Lista los dispositivos disponibles: emuladores, teléfonos o navegadores compatibles.

3. Abrir y ejecutar

En el equipo del docente, la carpeta principal para clase es actividad2a. Nosotros haremos las pruebas de guía en actividad2a-guia. Cada estudiante debe entrar a la ubicación donde guardó su propio proyecto.

Terminal · ejecutar desde la carpeta del proyecto
cd "C:\Users\user\Documents\DesarrolloMovilFlutter\actividad2a"
flutter pub get
flutter run
Línea 1 · cd

Cambia la carpeta de trabajo. Las comillas permiten usar rutas con espacios.

Línea 2 · flutter pub get

Obtiene las dependencias indicadas en pubspec.yaml. No es necesario repetirlo en cada ejecución si nada cambió.

Línea 3 · flutter run

Compila e inicia la aplicación en el dispositivo seleccionado. Si hay más de uno, Flutter puede pedirte elegir.

Atajo de clase

Con la aplicación ejecutándose desde la terminal, presiona r para Hot Reload cuando corresponda. El cambio se aplica sin reiniciar toda la aplicación. R hace un reinicio más completo.

Compila el proyecto y abre la interfaz. El proceso puede quedarse en ejecución mientras pruebas el programa: no significa que la terminal se haya bloqueado. Pulsa r para Hot Reload cuando Flutter lo permita y q para salir del modo interactivo.

¿Qué diferencia hay entre Hot Reload, Hot Restart y volver a ejecutar?

Hot Reload: intenta actualizar el código visual conservando el estado del programa. Es útil al modificar un texto o una propiedad de interfaz.

Hot Restart: vuelve a iniciar el código Dart de la aplicación y reinicia el estado de la app; suele servir cuando el cambio no quedó reflejado con Hot Reload.

Volver a ejecutar: cierra el proceso y realiza una nueva ejecución. Algunos cambios de configuración nativa o dependencias requieren un reinicio o una compilación nueva.

En la terminal de flutter run, r suele activar Hot Reload, R Hot Restart y q termina la ejecución. Estos atajos se usan en esa terminal, no dentro de la pantalla del teléfono.

Trae la biblioteca material.dart, que contiene los elementos de interfaz utilizados en este proyecto.

Es la función donde empieza la ejecución de Dart. void significa que esta función no devuelve un valor.

3. Las tres diferencias que más se confunden

¿Por qué se escribe const MainApp({super.key})?

MainApp es el nombre del constructor, igual al de la clase. La palabra const permite crear objetos constantes cuando sus parámetros y constructor cumplen los requisitos. El grupo {super.key} declara un parámetro nombrado opcional llamado key y lo transmite al constructor de la clase padre.

La key ayuda al framework a conservar o distinguir la identidad de widgets en determinadas reconstrucciones. No es una contraseña ni una clave de acceso. No es necesario que el estudiante asigne una clave a cada widget.

La línea termina en ; porque es una declaración de constructor abreviada, sin cuerpo con llaves.

¿Qué diferencia hay entre const, final y una variable normal?

const: para valores que deben conocerse como constantes en tiempo de compilación (por ejemplo const SizedBox(height: 20) cuando los argumentos son constantes).

final: permite asignar una variable solo una vez, aunque su valor puede obtenerse durante la ejecución; lo veremos cuando declaremos la lista final List<String> vehiculos = [...].

String busqueda = '': es una variable normal cuyo contenido podremos cambiar. No lleva final porque vamos a actualizarla con lo que escriba el usuario.

No todas las instancias pueden construirse con const. Si Dart señala un error, revisa si su constructor y sus argumentos permiten constancia.

¿Por qué hay return MaterialApp(...) en build?

La declaración Widget build(BuildContext context) indica que build debe devolver un Widget. La instrucción return entrega ese widget. MaterialApp(...) es el widget raíz construido para esta pantalla.

Los nombres entre paréntesis, como home: o body:, son argumentos nombrados. Los widgets se encuentran unos dentro de otros: Flutter utiliza esa jerarquía para formar el árbol de interfaz.

3. ¿Por qué usamos palabras como home, appBar, body y title?

Son nombres de argumentos definidos por los constructores de cada widget. Flutter reconoce cada nombre y sabe dónde colocar el valor asociado. No son variables que inventemos en el momento. Si escribimos mal el nombre, Dart puede mostrar un error de argumento inexistente.

4. Cómo seguir las aperturas y cierres

Cada Widget( necesita un ). Como los widgets están anidados, se cierran en el orden inverso en que se abrieron. No intentes cerrar Scaffold antes de cerrar el Center que se encuentra dentro. En el módulo 05 leeremos todos los cierres del archivo original con números de línea.

¿Por qué algunas expresiones llevan const y otras no?

const Text('Tienda') es válido porque su constructor y valor pueden ser constantes. En el archivo actual, MaterialApp y Scaffold no aparecen precedidos de const, aunque otras partes de la pantalla sí.

La regla práctica es: usa const cuando Dart lo permita y el editor lo recomiende, pero no supongas que todos los widgets necesitan esa palabra. La constancia se comprueba para cada expresión concreta.

    final resultados = vehiculos.where((vehiculo) {
      return vehiculo.toLowerCase().contains(
        busqueda.trim().toLowerCase(),
      );
    }).toList();

    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Tienda')),
        body: Padding(
          padding: const EdgeInsets.all(16),
          child: SingleChildScrollView(
            child: Column(

                        maxLines: 2,
                        overflow: TextOverflow.ellipsis,
                      ),
                    ),
                  ],
                ),
                const SizedBox(height: 12),
                TextField(
                  onChanged: (valor) {
                    setState(() {
                      busqueda = valor;
                    });
                  },
                  decoration: const InputDecoration(
                    hintText: 'Buscar marca o modelo',
                    border: OutlineInputBorder(),
                  ),
                ),
                const SizedBox(height: 12),
                Text('Estás buscando: $busqueda'),
                const SizedBox(height: 16),
                const Text('Vehículos encontrados:'),
                if (resultados.isEmpty)
                  const Text('No se encontraron vehículos.'),
                for (final vehiculo in resultados)
                  ListTile(
                    leading: const Icon(Icons.directions_car),
                    title: Text(vehiculo),
                  ),
                const SizedBox(height: 20),
                const Text('Agregar un vehículo'),
                const SizedBox(height: 10),
                TextField(
                  controller: nuevoVehiculoController,
                  decoration: const InputDecoration(
                    hintText: 'Ej. Toyota Corolla',
                    border: OutlineInputBorder(),
                  ),
                ),
                const SizedBox(height: 12),
                ElevatedButton(
                  onPressed: () {
                    final nombre = nuevoVehiculoController.text.trim();
                    if (nombre.isEmpty) return;
                    setState(() {
                      vehiculos.add(nombre);
                    });
                    nuevoVehiculoController.clear();
                  },
                  child: const Text('Agregar vehículo'),
                ),
              ],
            ),
          ),
        ),
      ),
    );
  }

AMPLIACIÓN · CONCEPTO BLoC

Comprender BLoC con el mismo buscador de actividad2a

Antes de incorporar un paquete o escribir una arquitectura, debemos entender qué problema resuelve. El ejemplo sigue siendo la Tienda: buscar, ver resultados y agregar vehículos.

1. Separar responsabilidades, sin aprender otro proyecto

En la versión sencilla, la clase State guarda la lista, el texto de búsqueda, las validaciones y el dibujo de widgets. Esto es apropiado para enseñar al principio. Cuando el programa crece, conviene que la pantalla no tenga que resolver todas esas tareas.

1

2

3

Recibe el evento, consulta los vehículos que conoce y decide cuáles coinciden. También puede aplicar reglas, validar o informar errores.

4. ¿Debemos usar BLoC desde el primer día?

No. Para una aplicación pequeña, setState ayuda a entender de forma visible qué significa cambiar datos y volver a dibujar la pantalla. BLoC es una alternativa para separar y coordinar responsabilidades cuando la complejidad lo justifique. En este taller enseñaremos primero la solución directa y solo después la versión organizada.
