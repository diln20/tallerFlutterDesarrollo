MÓDULO 01Código de clase15–20 min

Preparar y ejecutar el proyecto

Antes de escribir Flutter, comprobemos que nuestro entorno funciona y sepamos en qué carpeta vamos a trabajar.

✦
Al terminar podrás

Ubicar el proyecto, revisar el entorno de Flutter y abrir la aplicación en un dispositivo o emulador.

1. Reconocer el proyecto

Flutter organiza una aplicación en varias carpetas. Por ahora nos interesan estas tres piezas:

lib/main.dart

Es el archivo donde se encuentra el código Dart principal de la aplicación.

pubspec.yaml

Define el nombre del proyecto, la versión y las dependencias necesarias.

android/ y web/

Contienen archivos de soporte para ejecutar Flutter en distintas plataformas.

2. Comprobar Flutter

Abre PowerShell o la terminal de tu editor y ejecuta el diagnóstico. No modifica tus archivos.

Terminal · verificar instalación
flutter doctor
flutter devices
flutter doctor

Comprueba la instalación de Flutter y muestra herramientas que podrían faltar.

flutter devices

Lista los dispositivos disponibles: emuladores, teléfonos o navegadores compatibles.

3. Abrir y ejecutar

En el equipo del docente, la carpeta principal para clase es actividad2a. Nosotros haremos las pruebas de guía en actividad2a-guia. Cada estudiante debe entrar a la ubicación donde guardó su propio proyecto.

Terminal · ejecutar desde la carpeta del proyecto
cd "C:\Users\user\Documents\DesarrolloMovilFlutter\actividad2a"
flutter pub get
flutter run
Línea 1 · cd

Cambia la carpeta de trabajo. Las comillas permiten usar rutas con espacios.

Línea 2 · flutter pub get

Obtiene las dependencias indicadas en pubspec.yaml. No es necesario repetirlo en cada ejecución si nada cambió.

Línea 3 · flutter run

Compila e inicia la aplicación en el dispositivo seleccionado. Si hay más de uno, Flutter puede pedirte elegir.

Atajo de clase

Con la aplicación ejecutándose desde la terminal, presiona r para Hot Reload cuando corresponda. El cambio se aplica sin reiniciar toda la aplicación. R hace un reinicio más completo.

4. Verificar el resultado

MÓDULO 02Código de clase25–30 min

Entender main.dart desde la primera línea

Flutter no necesita que memorices todo de una vez. Primero entenderemos cómo arranca la aplicación y quién dibuja la pantalla.

✦
Al terminar podrás

Explicar con tus palabras qué hacen import, main, runApp, StatelessWidget, const, super.key y build.

1. Este es nuestro código de partida

El siguiente fragmento corresponde al comienzo del archivo lib/main.dart leído del proyecto de clase:

lib/main.dart · código real de actividad2a
import 'package:flutter/material.dart';

void main() {
  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Tienda')),
        // Aquí continúa el cuerpo de la pantalla.
      ),
    );
  }
}

El comentario sustituye visualmente el bloque body para estudiar el comienzo sin distracciones. No representa un cambio aplicado al archivo.

2. La explicación, línea por línea

1 · import

Trae la biblioteca material.dart, que contiene los elementos de interfaz utilizados en este proyecto.

2 · void main()

Es la función donde empieza la ejecución de Dart. void significa que esta función no devuelve un valor.

3 · runApp(...)

Entrega a Flutter el widget que será la raíz de la aplicación. En este caso es MainApp.

4 · const MainApp()

Crea una instancia del widget. const indica que su configuración puede tratarse como constante cuando sus valores lo permiten.

5 · class MainApp extends StatelessWidget

Define un widget propio. StatelessWidget significa que este widget no administra un estado mutable interno.

6 · const MainApp({super.key});

Es su constructor. super.key pasa una clave opcional a la clase padre; Flutter puede usarla para identificar widgets al reconstruir el árbol.

7 · @override

Indica que vamos a proporcionar nuestra implementación de un método heredado: build.

8 · Widget build(BuildContext context)

Es el método que describe qué interfaz debe construir Flutter. context informa dónde se encuentra este widget en el árbol.

9 · return MaterialApp(...)

Devuelve la interfaz de la aplicación, empezando por la configuración de Material Design.

3. Primero entiende este recorrido

main()
→
runApp()
→
MainApp
→
build()
→
MaterialApp
¿Cuándo usar const?

Úsalo si Dart permite crear el widget con argumentos constantes, por ejemplo const Text('Hola'). No todos los widgets ni todas las expresiones pueden ser constantes. No agregues const de forma automática: revisa si el editor lo sugiere.

MÓDULO 03Código de clase20–25 min

La estructura de nuestra pantalla

Antes de colocar textos, iconos o botones, necesitamos una estructura que los contenga.

✦
Al terminar podrás

Diferenciar el papel de MaterialApp, Scaffold, AppBar, body y Text.

1. Observa cómo se anidan los widgets

MainApp
MaterialApp
Scaffold
AppBar → Text('Tienda')
body → Center → Column

Piensa en una construcción: MaterialApp prepara el entorno visual, Scaffold distribuye la pantalla, AppBar muestra la barra superior y body contiene el espacio principal.

2. Lee el fragmento real

lib/main.dart · estructura actual
return MaterialApp(
  home: Scaffold(
    appBar: AppBar(title: const Text('Tienda')),
    body: Center(
      child: Column(
        children: [
          Text('Hello dsfdsWorld'),
          // Aquí hay más widgets.
        ],
      ),
    ),
  ),
);
Este fragmento simplifica la lista de hijos para estudiar su organización. El texto mostrado es el que figura en el código actual de clase.

3. Comprueba qué hace cada parte

MaterialApp

Configura la aplicación con los componentes de Material Design.

home:

Indica cuál será la pantalla inicial.

Scaffold

Proporciona una estructura común: barra superior y contenido.

appBar:

Asigna la barra superior. title: const Text('Tienda') coloca su título.

body:

Indica qué mostrar en la parte principal de la pantalla.

child frente a children

child recibe un widget; children recibe una lista de widgets entre corchetes.

¿Qué significan los dos puntos y los paréntesis?

En title: const Text('Tienda'), title es el nombre de un argumento y lo que sigue después de : es su valor. Los paréntesis ( ) contienen los argumentos con los que construimos un widget.

Hacer que la pantalla respire

Esta sección es una propuesta para la siguiente clase; todavía no está incorporada en el código original.

✦
Aprenderás

Agregar espacios a los bordes y permitir desplazamiento cuando la pantalla sea pequeña.

1. ¿Por qué agregar Padding?

Sin márgenes, los widgets pueden quedar pegados al borde. Padding deja un espacio interior alrededor de su hijo.

Propuesta · rodear el contenido con Padding
body: Padding(
  padding: const EdgeInsets.all(16),
  child: Center(
    child: Column(
      children: [
        const Text('Bienvenido a la tienda'),
      ],
    ),
  ),
),
padding: EdgeInsets.all(16)

Agrega 16 píxeles lógicos de margen interno a los cuatro lados.

child: Center(...)

Mantiene el contenido como hijo del nuevo widget. No reemplaza toda la pantalla por otro proyecto.

2. ¿Y si el contenido no cabe?

Cuando haya muchos elementos, un SingleChildScrollView puede permitir desplazarse verticalmente. Primero prueba el cambio en una copia, sin reescribir todo el archivo.

Propuesta · envolver una columna con scroll
SingleChildScrollView(
  child: Column(
    children: [
      const Text('Primera sección'),
      const SizedBox(height: 16),
      const Text('Segunda sección'),
    ],
  ),
)
No todo debe tener scroll

Úsalo cuando el contenido pueda sobrepasar la altura disponible. Para listas muy grandes aprenderemos después widgets especializados.

MÓDULO 07Siguiente práctica propuesta35–45 min

StatefulWidget: una interfaz que puede cambiar

Hasta ahora usamos StatelessWidget. ¿Qué hacemos si queremos mostrar en pantalla lo que escribió el usuario?

✦
Aprenderás

Diferenciar StatelessWidget de StatefulWidget y usar setState para actualizar una pantalla.

□

StatelessWidget

Describe una interfaz sin estado mutable administrado dentro de ese widget.

Ejemplo: título fijo
↻

StatefulWidget

Tiene un objeto de estado que puede cambiar y provocar una nueva construcción visual.

Ejemplo: contador o búsqueda

1. Crea primero la estructura con estado

En una copia para prácticas, reemplaza la declaración de un widget sencillo por esta estructura. Primero estudia el código; no necesitas introducir todavía un formulario.

Propuesta · estructura de StatefulWidget
class PantallaBusqueda extends StatefulWidget {
  const PantallaBusqueda({super.key});

  @override
  State<PantallaBusqueda> createState() =>
      _PantallaBusquedaState();
}

class _PantallaBusquedaState
    extends State<PantallaBusqueda> {
  String busqueda = '';

  @override
  Widget build(BuildContext context) {
    return Text('Buscando: $busqueda');
  }
}
StatefulWidget

Representa la parte del widget que conserva su configuración.

createState()

Crea el objeto encargado de mantener y actualizar el estado.

_PantallaBusquedaState

La clase guarda los datos que pueden cambiar. El guion bajo inicial hace privado ese nombre dentro de la biblioteca Dart.

String busqueda = ''

Guarda el texto actual; al principio está vacío.

$busqueda

Inserta el valor de una variable en una cadena. Esto se conoce como interpolación.

2. Haz que un evento cambie la pantalla

Una vez entendida la estructura anterior, añade un campo de texto dentro de un widget con estado y actualiza la variable.

Propuesta · contenido para el método build
Column(
  children: [
    TextField(
      onChanged: (valor) {
        setState(() {
          busqueda = valor;
        });
      },
    ),
    Text('Buscando: $busqueda'),
  ],
)
onChanged

Recibe una función que se ejecuta cuando el usuario modifica el texto.

valor

Es el nuevo texto recibido por la función.

setState(() { ... })

Avisa a Flutter que cambiaron datos de este widget y debe volver a construir su interfaz.

busqueda = valor

Guarda el texto actual para mostrarlo debajo.

3. ¿Y dispose() para qué sirve?

Más adelante, si utilizas un TextEditingController, tendrás que liberar ese recurso cuando el widget deje de existir:

Propuesta posterior · manejo de un controlador
final controlador = TextEditingController();

@override
void dispose() {
  controlador.dispose();
  super.dispose();
}

controlador.dispose() libera los recursos del controlador. super.dispose() permite que la clase padre complete su limpieza. No agregues un controlador si la práctica todavía no lo necesita.

✎ ACTIVIDAD INDIVIDUAL

Ver orientación

Dentro de setState(() { ... }) se puede escribir cantidad = cantidad + 1;. Una forma abreviada equivalente es cantidad++;.

MÓDULO 08Siguiente práctica propuesta35–45 min

Construir un formulario y validar sus datos

Cuando necesitamos que el usuario escriba información obligatoria, no basta con mostrar cajas de texto: también debemos comprobar lo que ingresa.

✦
Aprenderás

Comprender el propósito de Form, TextFormField, validator y un botón que ejecuta una acción.

1. Piensa primero en la lógica

  1. Mostrar el campo «Nombre del cliente».
  2. Permitir que el usuario escriba.
  3. Al pulsar «Guardar», comprobar que no esté vacío.
  4. Mostrar un mensaje de error o continuar.

2. Implementar la validación

Esta práctica presupone que ya conocemos cómo administrar estado. El ejemplo se integra dentro de una clase State; primero hay que declarar su clave.

Propuesta · declarar la clave dentro de State
final _formKey = GlobalKey<FormState>();

La clave nos permite acceder al estado del formulario y pedirle que se valide.

Propuesta · contenido del método build
Form(
  key: _formKey,
  child: Column(
    children: [
      TextFormField(
        decoration: const InputDecoration(
          labelText: 'Nombre del cliente',
        ),
        validator: (valor) {
          if (valor == null || valor.trim().isEmpty) {
            return 'Escribe un nombre';
          }
          return null;
        },
      ),
      ElevatedButton(
        onPressed: () {
          if (_formKey.currentState!.validate()) {
            ScaffoldMessenger.of(context).showSnackBar(
              const SnackBar(
                content: Text('Datos válidos'),
              ),
            );
          }
        },
        child: const Text('Guardar'),
      ),
    ],
  ),
)
Form(key: _formKey)

Agrupa los campos y los relaciona con una clave.

TextFormField

Es un campo de texto que puede participar en la validación del formulario.

validator: (valor)

Ejecuta una función que devuelve un mensaje de error o null cuando el dato es válido.

trim()

Elimina espacios al comienzo y al final; así, un campo con solo espacios también se considera vacío.

onPressed

Indica qué debe pasar al pulsar el botón.

validate()

Evalúa las funciones de validación de los campos del formulario.

SnackBar

Muestra un aviso breve dentro de la aplicación cuando la validación pasa.

Sobre el operador !

En _formKey.currentState!.validate(), el signo ! afirma que el estado no es nulo. En esta práctica se asume que el formulario está montado y vinculado a la clave. Más adelante veremos el manejo seguro de valores nulos.

3. Primera representación de datos

Cuando estudiemos variables y estado, podremos utilizar algo como esto:

1. Una analogía cotidiana

Piensa en un cajero automático real. La pantalla recibe una instrucción, un sistema verifica la operación y después la pantalla muestra el resultado. No hace falta que la pantalla conozca todos los cálculos internos.

2. Comparar las dos versiones

1

Primero: sin BLoC

La propia pantalla mantiene el saldo y llama a setState. Es fácil de entender para comenzar.

2

Después: con BLoC

La pantalla envía una acción. El BLoC procesa las reglas y produce un nuevo estado que la pantalla muestra.

Importante para nuestro taller

No mezclaremos BLoC con las primeras explicaciones de Column, Row o TextField. Primero terminaremos una versión funcional sin BLoC; después la evolucionaremos de forma guiada.

3. Vocabulario esencial

Evento

Representa una acción o solicitud, por ejemplo «Retirar 20.000».

BLoC

Procesa eventos y define cómo debe evolucionar el estado según las reglas.

Estado

Es la información necesaria para representar la situación actual: saldo disponible, operación correcta o mensaje de error.

Interfaz

Dibuja lo que el usuario ve a partir del estado. No debería concentrar toda la lógica de negocio.
