Preparar y ejecutar el proyecto

Antes de escribir Flutter, comprobemos que nuestro entorno funciona y sepamos en qué carpeta vamos a trabajar.

✦
Al terminar podrás

Ubicar el proyecto, revisar el entorno de Flutter y abrir la aplicación en un dispositivo o emulador.

1. Reconocer el proyecto

Flutter organiza una aplicación en varias carpetas. Por ahora nos interesan estas tres piezas:

lib/main.dart

Es el archivo donde se encuentra el código Dart principal de la aplicación.

pubspec.yaml

Define el nombre del proyecto, la versión y las dependencias necesarias.

android/ y web/

Contienen archivos de soporte para ejecutar Flutter en distintas plataformas.

2. Comprobar Flutter

Abre PowerShell o la terminal de tu editor y ejecuta el diagnóstico. No modifica tus archivos.

Terminal · verificar instalación
flutter doctor
flutter devices
flutter doctor

Comprueba la instalación de Flutter y muestra herramientas que podrían faltar.

flutter devices

Lista los dispositivos disponibles: emuladores, teléfonos o navegadores compatibles.

3. Abrir y ejecutar

En el equipo del docente, la carpeta principal para clase es actividad2a. Nosotros haremos las pruebas de guía en actividad2a-guia. Cada estudiante debe entrar a la ubicación donde guardó su propio proyecto.

Terminal · ejecutar desde la carpeta del proyecto
cd "C:\Users\user\Documents\DesarrolloMovilFlutter\actividad2a"
flutter pub get
flutter run
Línea 1 · cd

Cambia la carpeta de trabajo. Las comillas permiten usar rutas con espacios.

Línea 2 · flutter pub get

Obtiene las dependencias indicadas en pubspec.yaml. No es necesario repetirlo en cada ejecución si nada cambió.

Línea 3 · flutter run

Compila e inicia la aplicación en el dispositivo seleccionado. Si hay más de uno, Flutter puede pedirte elegir.

Atajo de clase

Con la aplicación ejecutándose desde la terminal, presiona r para Hot Reload cuando corresponda. El cambio se aplica sin reiniciar toda la aplicación. R hace un reinicio más completo.

1. Este es nuestro código de partida

El siguiente fragmento corresponde al comienzo del archivo lib/main.dart leído del proyecto de clase:

lib/main.dart · código real de actividad2a
import 'package:flutter/material.dart';

void main() {
  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Tienda')),
        // Aquí continúa el cuerpo de la pantalla.
      ),
    );
  }
}

El comentario sustituye visualmente el bloque body para estudiar el comienzo sin distracciones. No representa un cambio aplicado al archivo.

2. La explicación, línea por línea

1 · import

Trae la biblioteca material.dart, que contiene los elementos de interfaz utilizados en este proyecto.

2 · void main()

Es la función donde empieza la ejecución de Dart. void significa que esta función no devuelve un valor.

3 · runApp(...)

Entrega a Flutter el widget que será la raíz de la aplicación. En este caso es MainApp.

4 · const MainApp()

Crea una instancia del widget. const indica que su configuración puede tratarse como constante cuando sus valores lo permiten.

5 · class MainApp extends StatelessWidget

Define un widget propio. StatelessWidget significa que este widget no administra un estado mutable interno.

6 · const MainApp({super.key});

Es su constructor. super.key pasa una clave opcional a la clase padre; Flutter puede usarla para identificar widgets al reconstruir el árbol.

7 · @override

Indica que vamos a proporcionar nuestra implementación de un método heredado: build.

8 · Widget build(BuildContext context)

Es el método que describe qué interfaz debe construir Flutter. context informa dónde se encuentra este widget en el árbol.

9 · return MaterialApp(...)

Devuelve la interfaz de la aplicación, empezando por la configuración de Material Design.

¿Cuándo usar const?

Úsalo si Dart permite crear el widget con argumentos constantes, por ejemplo const Text('Hola'). No todos los widgets ni todas las expresiones pueden ser constantes. No agregues const de forma automática: revisa si el editor lo sugiere.

  home: Scaffold(
    appBar: AppBar(title: const Text('Tienda')),

3. Comprueba qué hace cada parte

MaterialApp

Configura la aplicación con los componentes de Material Design.

home:

Indica cuál será la pantalla inicial.

Scaffold

Proporciona una estructura común: barra superior y contenido.

appBar:

Asigna la barra superior. title: const Text('Tienda') coloca su título.

body:

Indica qué mostrar en la parte principal de la pantalla.

child frente a children

child recibe un widget; children recibe una lista de widgets entre corchetes.

¿Qué significan los dos puntos y los paréntesis?

En title: const Text('Tienda'), title es el nombre de un argumento y lo que sigue después de : es su valor. Los paréntesis ( ) contienen los argumentos con los que construimos un widget.

1. ¿Por qué ahora necesitamos un estado?

Hoy MainApp extends StatelessWidget. Para mostrar en pantalla lo que el usuario escribe, la clase administrará un valor cambiante: busqueda.

□

StatelessWidget, versión actual

Presenta los widgets que ya existen, sin guardar cambios locales de búsqueda.

↻

StatefulWidget, nueva propuesta

Permite guardar el texto y reconstruir la Tienda cuando cambia.

2. Transformar la clase MainApp

Conserva main() y runApp(const MainApp()) tal como están. Reemplaza la clase MainApp por una versión con estado; dentro de su método build, conserva la pantalla MaterialApp → Scaffold → Tienda actual.

PROPUESTA · estructura de MainApp con estado
class MainApp extends StatefulWidget {
  const MainApp({super.key});

  @override
  State<MainApp> createState() => _MainAppState();
}

class _MainAppState extends State<MainApp> {
  String busqueda = '';

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      // Conserva aquí la pantalla Scaffold actual.
    );
  }
}
StatefulWidget

Permite que el widget tenga un objeto State asociado.

createState()

Crea el objeto encargado de administrar los datos que cambian.

State<MainApp>

Indica que ese estado pertenece a MainApp.

String busqueda = ''

Declara el texto que iremos actualizando; inicialmente está vacío.

build

Continúa construyendo la misma pantalla «Tienda» que conocemos.

3. Agregar onChanged al TextField actual

Busca el campo «Buscar marca o modelo» dentro de la Row, o debajo si ya aplicaste el módulo anterior. Agrega un solo argumento nuevo: onChanged.

PROPUESTA · cambiar solo el TextField
TextField(
  onChanged: (valor) {
    setState(() {
      busqueda = valor;
    });
  },
  decoration: const InputDecoration(
    hintText: 'Buscar marca o modelo',
  ),
),
onChanged

Se ejecuta cuando el usuario modifica el texto.

valor

Recibe el texto actual del campo.

setState(() { ... })

Avisa a Flutter que cambió un valor del State.

busqueda = valor

PROPUESTA · declaraciones y limpieza del State

TextEditingController

3. Agregar el formulario debajo de los resultados

Este bloque se colocará en la Column de la misma Tienda, después del listado.

PROPUESTA · formulario y botón
Form(
  key: formularioKey,
  child: Column(
    children: [
      TextFormField(
        controller: nuevoVehiculoController,
        decoration: const InputDecoration(
          labelText: 'Nombre del vehículo',
        ),
        validator: (valor) {
          if (valor == null || valor.trim().isEmpty) {
            return 'Escribe un nombre';
          }
          return null;
        },
      ),
      ElevatedButton(
        onPressed: () {
          if (formularioKey.currentState?.validate() != true) {
            return;
          }
          setState(() {
            vehiculos.add(
              nuevoVehiculoController.text.trim(),
            );
          });
          nuevoVehiculoController.clear();
        },
        child: const Text('Agregar vehículo'),
      ),
    ],
  ),
),
Form y key

Agrupan los campos y vinculan la clave para validar.

TextFormField

Permite escribir un dato que requiere validación.

validator

Devuelve el error «Escribe un nombre» si el texto está vacío o solo tiene espacios.

?.validate() != true

Detiene la acción si no se pudo validar correctamente.

vehiculos.add(...)

Agrega un nombre válido a la lista local que ya estamos filtrando.

setState

Indica que la lista cambió y debemos reconstruir el resultado visible.

clear()

Deja el campo vacío para la próxima entrada.

Alcance de esta práctica

Los nombres agregados quedan solo en la memoria de la aplicación. No se guardan en una base de datos ni permanecen al reiniciar. Este comportamiento es adecuado para aprender formularios primero.
