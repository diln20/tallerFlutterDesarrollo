Ruta de aprendizaje

Primero mejoramos el catálogo que ya existe y luego introducimos el modelo Usuario. No sustituimos el objeto Vehiculo, ni implementamos autenticación real antes de explicar los conceptos.

Antes de continuar: migración obligatoria del modelo

0. Ampliar Vehiculo sin perder imágenes

La versión inicial del taller tiene Vehiculo(nombre, disponible). La etapa de fotografías agrega imagenBytes. Los pasos de filtros, favoritos y precios requieren primero añadir id, marca y precio. No se debe reemplazar el modelo por una copia anterior sin imágenes.

Archivo exacto: lib/models/vehiculo.dart. En este punto reemplaza la definición de la clase por la versión acumulativa siguiente:

import 'dart:typed_data';

class Vehiculo {
  const Vehiculo({
    required this.id,
    required this.nombre,
    required this.marca,
    required this.precio,
    this.disponible = true,
    this.imagenBytes,
  });

  final int id;
  final String nombre;
  final String marca;
  final double precio;
  final bool disponible;
  final Uint8List? imagenBytes;
}

La clase conserva disponible e imagenBytes y agrega id, marca y precio. Este cambio requiere adaptar previamente el formulario y los lugares que llaman a Vehiculo(...) para suministrar los tres campos nuevos; mientras no se adapte el formulario, no ejecutes esta migración. Puedes mantener temporalmente la etapa de imágenes sin filtros avanzados.

El id debe permanecer estable al editar y ser generado de forma única por el repositorio o la API; nunca uses como identificador permanente la posición de un elemento en ListView. Para la aplicación completa, la API debería generar los identificadores persistentes. El repositorio en memoria de la etapa anterior no es todavía una implementación de estos cambios.

Parte A · Evolución del listado de vehículos

1. Ubicar los archivos

Trabaja dentro del proyecto actividad2. Mantén lib/models/vehiculo.dart y la página donde se muestra el catálogo. Los fragmentos siguientes van dentro del State de esa página, NO dentro del método build.

2. Crear variables de estado

String busqueda = '';
String marcaSeleccionada = 'Todas';
double precioMaximo = 200000000;
String orden = 'Nombre';
final Set<int> favoritos = {};
int paginaActual = 0;
final int elementosPorPagina = 5;

String almacena texto; double, un número con decimales; Set<int> conserva identificadores sin repetirlos; final impide reasignar la variable (pero el Set puede cambiar). La página comienza en cero.

3. Construir la lista filtrada

Este ejemplo depende de completar el paso 0 y adaptar el formulario, el repositorio y la creación de objetos a id, nombre, marca y precio. No corresponde todavía al proyecto ejecutable de la etapa de fotografías.

List<Vehiculo> filtrarVehiculos(List<Vehiculo> vehiculos) {
  final resultado = vehiculos.where((vehiculo) {
    final coincideTexto = vehiculo.nombre
        .toLowerCase()
        .contains(busqueda.toLowerCase().trim());
    final coincideMarca = marcaSeleccionada == 'Todas' ||
        vehiculo.marca == marcaSeleccionada;
    final coincidePrecio = vehiculo.precio <= precioMaximo;
    return coincideTexto && coincideMarca && coincidePrecio;
  }).toList();

  if (orden == 'Precio menor') {
    resultado.sort((a, b) => a.precio.compareTo(b.precio));
  } else if (orden == 'Precio mayor') {
    resultado.sort((a, b) => b.precio.compareTo(a.precio));
  } else {
    resultado.sort((a, b) => a.nombre.compareTo(b.nombre));
  }
  return resultado;
}

where revisa cada vehículo; && exige que se cumplan las tres condiciones; toList() crea una lista concreta; sort cambia el orden. La función no altera la lista original.

5. Dibujar resultados y paginarlos

final filtrados = filtrarVehiculos(vehiculos);
final inicio = paginaActual * elementosPorPagina;
final visibles = filtrados.skip(inicio)
    .take(elementosPorPagina).toList();

Ubicación: estas tres instrucciones van al inicio de build, antes de return Scaffold(...), donde vehiculos es la lista actual de tu pantalla.

filtrados.isEmpty
    ? const Center(child: Text('No se encontraron vehículos'))
    : ListView.builder(
        shrinkWrap: true,
        physics: const NeverScrollableScrollPhysics(),
        itemCount: visibles.length,
        itemBuilder: (context, index) {
          final vehiculo = visibles[index];
          return ListTile(
            title: Text(vehiculo.nombre),
            subtitle: Text(vehiculo.marca),
            trailing: IconButton(
              icon: Icon(favoritos.contains(vehiculo.id)
                  ? Icons.favorite
                  : Icons.favorite_border),
              onPressed: () {
                setState(() {
                  if (!favoritos.add(vehiculo.id)) {
                    favoritos.remove(vehiculo.id);
                  }
                });
              },
            ),
          );
        },
      ),

itemCount determina cuántas filas dibujar; itemBuilder construye cada fila; index identifica la posición; ListTile agrupa título, subtítulo y acción. shrinkWrap y la física sin desplazamiento propio se usan aquí solamente si el listado está dentro de otro contenedor vertical desplazable.

Parte B · Un segundo objeto: Usuario

El objeto Vehiculo contiene datos del carro. El nuevo objeto Usuario representa a la persona que utiliza el sistema y su rol. El rol describe qué operaciones puede realizar, no qué vehículo es.

7. Crear el archivo lib/models/usuario.dart

enum RolUsuario { administrador, vendedor, cliente }

class Usuario {
  final int id;
  final String nombre;
  final String correo;
  final RolUsuario rol;

  const Usuario({
    required this.id,
    required this.nombre,
    required this.correo,
    required this.rol,
  });
}

enum limita los roles a tres valores válidos; class define el molde; final conserva los datos asignados; required obliga a enviarlos al construir el objeto; const permite crear instancias constantes cuando todos sus valores también lo son. Las contraseñas nunca deben almacenarse como texto simple en este modelo.

10. Centralizar permisos en lib/models/permiso.dart

import 'usuario.dart';

enum Permiso {
  verCatalogo,
  crearVehiculo,
  editarVehiculo,
  eliminarVehiculo,
  gestionarUsuarios,
  agregarFavoritos,
}

bool tienePermiso(Usuario usuario, Permiso permiso) {
  switch (usuario.rol) {
    case RolUsuario.administrador:
      return true;
    case RolUsuario.vendedor:
      return permiso == Permiso.verCatalogo ||
          permiso == Permiso.crearVehiculo ||
          permiso == Permiso.editarVehiculo ||
          permiso == Permiso.agregarFavoritos;
    case RolUsuario.cliente:
      return permiso == Permiso.verCatalogo ||
          permiso == Permiso.agregarFavoritos;
  }
}

switch examina el rol; || significa «o»; la función devuelve true únicamente cuando la operación está permitida. Con esta función evitamos repetir reglas diferentes en cada botón.

11. Mostrar botones según el rol

En la página del catálogo, importa usuario.dart y permiso.dart. Recibe el Usuario usuarioActual por constructor y usa esta condición dentro de la lista de botones:

if (tienePermiso(usuarioActual, Permiso.crearVehiculo))
  ElevatedButton(
    onPressed: () {
      // Aquí se llamará la navegación al formulario.
    },
    child: const Text('Agregar vehículo'),
  ),

El if dentro de children: [] es una colección condicional de Dart; si el permiso es falso, el botón no se agrega al árbol de widgets. No hace falta instalar un paquete para esta explicación inicial.

14. Seguridad real: autenticación y autorización

Autenticación responde quién es la persona: por ejemplo, mediante inicio de sesión y token válido. Autorización responde qué puede hacer esa persona. Aunque Flutter oculte el botón «Eliminar», un cliente podría intentar invocar la API directamente. Por eso el backend debe verificar el token, recuperar el rol desde una fuente confiable y denegar la operación si no está autorizada (por ejemplo con HTTP 403). Nunca aceptes un rol enviado libremente desde la interfaz como prueba de permisos.
